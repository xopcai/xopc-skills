# Scenario Brief: design-distinctive-web-interface

## User and outcome

Product teams and builders need a new or substantially redesigned web interface that looks specific to their product instead of a generic generated template. The deliverable is working interface code plus a coherent visual direction and rendered verification.

Success means the hierarchy serves one stated page job, the design derives from the real subject, supplied framework and brand constraints remain intact, mobile and keyboard paths work, and screenshots reveal no critical layout or state defect.

## Boundaries

- Not for tiny CSS adjustments, backend-only work, brand invention without a brief, or unsupported marketing claims.
- Rendering, screenshot, and accessibility evidence are preferred; unavailable checks must be disclosed.
- Existing design systems and user-selected frameworks are preserved unless change is explicitly requested.

## Evaluation

Fixtures cover a new landing page, existing dashboard redesign, strict brand brief, sparse content, reduced-motion requirement, and a near-miss one-line style fix. Human review scores specificity, hierarchy, visual coherence, responsive behavior, and truthful content.
