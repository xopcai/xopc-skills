# Scenario Brief: address-github-review-comments

## User and outcome

Pull request authors need review threads grouped, selected, implemented, verified, and answered without treating every comment as correct or current.

## Boundaries

- Not initial code review or CI failure diagnosis.
- Code edits, replies, thread resolution, and pushes are distinct permissions.
- Stale and incorrect feedback is handled with evidence.

## Evaluation

Fixtures include duplicate, stale, conflicting, already-addressed, question-only, and actionable comments across resolved and unresolved threads.
