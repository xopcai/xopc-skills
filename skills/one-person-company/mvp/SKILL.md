# MVP

Start with the evidence already earned and name the single riskiest remaining assumption. Define one customer, one job, one end-to-end outcome and one observable learning question. If a manual process can answer it faster and more safely, prefer that over software.

Create an in/out/later scope. Keep only the minimum path required for the customer to receive and evaluate the promised outcome, plus necessary privacy, security, payment, accessibility and recovery controls. Exclude dashboards, roles, integrations, automation, polish and scale work unless the experiment cannot function without them.

Specify the experiment cohort, instrumentation, acceptance criteria, failure criteria, time and cash cap, support plan, and how customer data or payments will be handled. A time box alone is not an outcome. Do not call a mockup an MVP when it cannot deliver the tested value, and do not expose live users to an unsafe prototype.

Return the hypothesis, evidence baseline, thin user journey, scoped backlog, non-goals, test plan, release safeguards and explicit stop/revise/continue rule. Separate learning code from production commitments and record what must be rebuilt before scale.
